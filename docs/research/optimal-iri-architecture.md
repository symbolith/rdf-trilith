# Optimal IRI Architecture Design

**Research Date:** 2026-01-29
**Objective:** Define the optimal type architecture for a universal IRI library

---

## Executive Summary

The optimal IRI architecture uses a **three-tier type system**:

1. **`Iri(str)`** - Unsized DST wrapper for validation (16 bytes borrowed)
2. **`IriBuf(String)`** - Owned validated string (24 bytes)
3. **`Components<S>`** - Generic with pre-computed positions, O(1) access
   - `Components<&Iri>` — borrowed, zero-alloc (32 bytes stack)
   - `Components<IriBuf>` — owned (40 bytes stack + 1 heap allocation)

---

## 1. Type Definitions

### 1.1 Iri(str) - Transparent Borrowed Wrapper

```rust
#[repr(transparent)]
#[derive(Debug, PartialEq, Eq, Hash)]
pub struct Iri(str);

impl Iri {
    pub fn new(s: &str) -> Result<&Self, IriError>;
    pub unsafe fn new_unchecked(s: &str) -> &Self;
    pub fn as_str(&self) -> &str;

    pub fn scheme(&self) -> &Scheme;
    pub fn authority(&self) -> Option<&Authority>;
    pub fn path(&self) -> &Path;
    pub fn query(&self) -> Option<&Query>;
    pub fn fragment(&self) -> Option<&Fragment>;
}
```

**Memory Layout:**
```text
&Iri (fat pointer):
├─ ptr: *const u8     (8 bytes)
└─ len: usize         (8 bytes)
Total: 16 bytes
```

**Use when:** Need validation with occasional component access. Accessors re-parse on each call (O(n)); use `Components<&Iri>` for repeated access.

---

### 1.2 Component Newtypes — Borrowed `str` Wrappers

Every IRI component (scheme, authority, path, query, fragment) is a validated subset of `str`, so each gets its own `#[repr(transparent)]` newtype. These are borrowed-only — no `Buf` variants needed since components are always slices into a parent IRI string.

```rust
#[repr(transparent)]
pub struct Scheme(str);

#[repr(transparent)]
pub struct Authority(str);

#[repr(transparent)]
pub struct Path(str);

#[repr(transparent)]
pub struct Query(str);

#[repr(transparent)]
pub struct Fragment(str);
```

Each follows the same API pattern as `Iri`:

```rust
impl Scheme {
    pub fn new(s: &str) -> Result<&Self, IriError>;
    pub unsafe fn new_unchecked(s: &str) -> &Self;
    pub fn as_str(&self) -> &str;
}
```

(Same pattern for `Authority`, `Path`, `Query`, `Fragment`.)

**Memory Layout:**
```text
&Scheme / &Authority / &Path / &Query / &Fragment (fat pointer):
├─ ptr: *const u8     (8 bytes)
└─ len: usize         (8 bytes)
Total: 16 bytes (identical to &str)
```

**Key Points:**
- `Path` is module-scoped (`iri::Path`) — not reusable from `std::path::Path` which wraps `OsStr`
- No owned variants: component types always borrow from the parent `Iri`/`IriBuf`/`Components<S>` string
- `#[repr(transparent)]` means `&Scheme` has identical layout to `&str`, zero-cost

---

### 1.3 Refinement Macros

The boilerplate for `Iri`, `IriBuf`, and every component newtype is generated by two declarative macros. Each macro takes a visibility, type name, validation function, and error type, and expands to the full struct definition with all trait impls.

#### `refined_str!` — Borrowed `str` Wrapper

Generates an unsized `#[repr(transparent)]` newtype over `str` (borrowed-only):

```rust
refined_str!(pub Scheme, validate_scheme => SchemeError);
refined_str!(pub Authority, validate_authority => AuthorityError);
refined_str!(pub Path, validate_path => PathError);
refined_str!(pub Query, validate_query => QueryError);
refined_str!(pub Fragment, validate_fragment => FragmentError);
refined_str!(pub Iri, validate_iri => IriError);
```

**Expansion produces:**

```rust
#[repr(transparent)]
pub struct Scheme(str);

impl Scheme {
    pub fn new(s: &str) -> Result<&Self, SchemeError> { ... }
    pub unsafe fn new_unchecked(s: &str) -> &Self { ... }
    pub fn as_str(&self) -> &str { ... }
}
```

**Generated trait impls:** `Deref<Target=str>`, `AsRef<str>`, `Borrow<str>`, `Display`, `Debug`, `PartialEq`, `Eq`, `Hash`, `PartialOrd`, `Ord`.

#### `refined_string!` — Owned `String` Wrapper

Generates an owned `String` newtype linked to its borrowed counterpart:

```rust
refined_string!(pub IriBuf for Iri, validate_iri => IriError);
```

**Expansion produces:**

```rust
pub struct IriBuf(String);

impl IriBuf {
    pub fn new(s: String) -> Result<Self, IriError> { ... }
    pub fn as_str(&self) -> &str { ... }
    pub fn into_string(self) -> String { ... }
}
```

**Generated trait impls:** `Deref<Target=Iri>`, `AsRef<str>`, `AsRef<Iri>`, `Borrow<str>`, `Borrow<Iri>`, `ToOwned for Iri` (with `Owned = IriBuf`), `From<&Iri>`, `Clone`, `Display`, `Debug`, `PartialEq` (including cross-type with `&Iri`), `Eq`, `Hash`, `PartialOrd`, `Ord`.

#### Validation Function Contract

Every validation function has the signature:

```rust
fn validate(input: &str) -> Result<(), E>;
```

The macro calls this function inside `new`, returning `Err(E)` on invalid input and transmuting the `&str` to `&Self` on success (safe because `#[repr(transparent)]`).

#### Validation Strategy Per Component

| Component | Strategy | Reason |
|-----------|----------|--------|
| `Scheme` | `[bool; 256]` lookup table | Every byte independently valid/invalid (`ALPHA *( ALPHA / DIGIT / "+" / "-" / "." )`) |
| `Path` | `[bool; 256]` lookup table | Per-byte character class check (`pchar / "/" / ...`) |
| `Query` | `[bool; 256]` lookup table | Per-byte character class check (`pchar / "/" / "?" / iprivate`) |
| `Fragment` | `[bool; 256]` lookup table | Per-byte character class check (same as query minus iprivate) |
| `Authority` | State machine | Context-dependent: `@` separates userinfo from host, `:` separates host from port but also appears in IPv6 `[::1]`, brackets delimit IP-literal |
| `Iri` | State machine | Full grammar requires tracking component boundaries in sequence |

The lookup table approach compiles to a single array index per byte — branch-free and cache-friendly. Authority and full IRI validation require a state machine because the meaning of delimiter characters depends on position within the string.

### 1.4 IriBuf(String) - Owned Tuple Struct

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct IriBuf(String);

impl IriBuf {
    pub fn new(s: String) -> Result<Self, IriError>;
    pub fn as_str(&self) -> &str;
    pub fn as_iri(&self) -> &Iri;
    pub fn components(&self) -> Components<IriBuf>;
}
```

**Memory Layout:**
```text
IriBuf(String):
├─ ptr: *mut u8       (8 bytes)
├─ len: usize         (8 bytes)
└─ capacity: usize    (8 bytes)
Total: 24 bytes
```

**Deref to Iri:** `IriBuf` gains `scheme()`, `authority()`, `path()`, `query()`, `fragment()` via `Deref<Target=Iri>`. These re-parse on each call (O(n)); use `.components()` for repeated access.

**Use when:**
- Need to own the IRI
- Store in struct without lifetimes
- Don't need frequent component access (can call .components() when needed)

---

### 1.5 Components\<S\> - Generic with Positions

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct Components<S> {
    iri: S,
    scheme_end: u32,
    authority_end: u32,
    path_end: u32,
    query_end: u32,
}
```

#### Shared Accessors

All accessors are available for any `S: Borrow<Iri>`:

```rust
impl<S: Borrow<Iri>> Components<S> {
    pub fn scheme(&self) -> &Scheme;
    pub fn authority(&self) -> Option<&Authority>;
    pub fn path(&self) -> &Path;
    pub fn query(&self) -> Option<&Query>;
    pub fn fragment(&self) -> Option<&Fragment>;
    pub fn as_iri(&self) -> &Iri;
    pub fn as_str(&self) -> &str;
}
```

#### Borrowed Variant: Components<&Iri>

```rust
impl<'a> Components<&'a Iri> {
    pub fn new(iri: &'a Iri) -> Self;
    pub fn parse(s: &'a str) -> Result<Self, IriError>;
    pub fn to_owned(&self) -> Components<IriBuf>;
}
```

#### Owned Variant: Components\<IriBuf\>

```rust
impl Components<IriBuf> {
    pub fn new(iri: IriBuf) -> Self;
    pub fn parse(s: String) -> Result<Self, IriError>;
    pub fn into_iri_buf(self) -> IriBuf;
    pub fn as_borrowed(&self) -> Components<&Iri>;
}
```

**Memory Layouts:**
```text
Components<&Iri>:                       Components<IriBuf>:
├─ iri: &Iri  (16 B, fat ptr)          ├─ iri: IriBuf  (24 B)
├─ scheme_end     (4 B)                ├─ scheme_end      (4 B)
├─ authority_end  (4 B)                ├─ authority_end   (4 B)
├─ path_end       (4 B)                ├─ path_end        (4 B)
├─ query_end      (4 B)                ├─ query_end       (4 B)
Total: 32 B, 0 heap                    Total: 40 B, 1 heap
```

**Key Point: Generic Over Storage**

`Components<S>` is generic over its backing storage. Use `Components<&Iri>` for temporary, zero-allocation parsing; use `Components<IriBuf>` when you need to own the data and store it in structs or send across threads. Both variants share the same O(1) accessors via the `Borrow<Iri>` bound.

```rust
// ✅ Borrowed - zero allocation, temporary parsing
let borrowed = Components::parse("http://example.com")?;
println!("{}", borrowed.scheme());

// ✅ Owned - from validated IriBuf
let owned_iri = IriBuf::new("http://example.com".to_string())?;
let owned = Components::new(owned_iri);

// ✅ Owned - from raw string
let owned = Components::parse("http://example.com".to_string())?;

// ✅ Convert between variants
let owned = borrowed.to_owned();
let re_borrowed = owned.as_borrowed();

// ✅ Get &Iri back for free
let iri_ref: &Iri = owned.as_iri();

// ✅ Drop positions, recover the IriBuf
let iri_buf: IriBuf = owned.into_iri_buf();
```

**Use when:**
- `Components<&Iri>` — Temporary parsing, zero allocation, bounded by lifetime
- `Components<IriBuf>` — Own the IRI with positions, store in structs, send across threads

## 2. Type System Summary

### Complete Type Hierarchy

All refinement types are declared via macros (see §1.3):

```rust
refined_str!(pub Iri, validate_iri => IriError);
refined_string!(pub IriBuf for Iri, validate_iri => IriError);

refined_str!(pub Scheme, validate_scheme => SchemeError);
refined_str!(pub Authority, validate_authority => AuthorityError);
refined_str!(pub Path, validate_path => PathError);
refined_str!(pub Query, validate_query => QueryError);
refined_str!(pub Fragment, validate_fragment => FragmentError);
```

These expand to:

```rust
#[repr(transparent)]
pub struct Iri(str);

pub struct IriBuf(String);

#[repr(transparent)]
pub struct Scheme(str);

#[repr(transparent)]
pub struct Authority(str);

#[repr(transparent)]
pub struct Path(str);

#[repr(transparent)]
pub struct Query(str);

#[repr(transparent)]
pub struct Fragment(str);
```

`Components<S>` is not a refinement type — it's a plain struct with pre-computed positions:

```rust
pub struct Components<S> {
    iri: S,
    scheme_end: u32,
    authority_end: u32,
    path_end: u32,
    query_end: u32,
}
```

### Type Selection Guide

| Need | Use Type | Reason |
|------|----------|--------|
| Validate + occasional access | `&Iri` | Minimal (16 bytes), O(n) component access |
| Own + occasional access | `IriBuf` | Simple wrapper (24 bytes), O(n) via Deref |
| Parse temporarily | `Components<&Iri>` | Zero-alloc O(1) access (32 bytes) |
| Own with O(1) component access | `Components<IriBuf>` | Positions cached (40 bytes + 1 heap alloc) |
| Store in struct | `IriBuf` or `Components<IriBuf>` | No lifetime issues |

### Performance Characteristics

| Type | Stack | Heap | Component Access |
|------|-------|------|------------------|
| `&Iri` | 16 bytes | 0 | O(n) re-parse |
| `IriBuf` | 24 bytes | 1 alloc | O(n) via Deref to Iri |
| `Components<&Iri>` | 32 bytes | 0 | O(1) |
| `Components<IriBuf>` | 40 bytes | 1 alloc | O(1) |

### Conversion Paths

```text
&str ──validate──► &Iri ──parse positions──► Components<&Iri>
                     │                           │
                     │                       to_owned()
                     │                           │
String ──validate──► IriBuf ──parse positions──► Components<IriBuf>
                     ▲                              │  ▲
                     └──── into_iri_buf() ──────────┘  │
                                                       │
                              as_borrowed() ───────────┘
```

## 3. Usage Examples

### Validation Only

```rust
fn accept_iri(iri: &Iri) {
    println!("Valid IRI: {}", iri.as_str());
}

let s = "http://example.com";
let validated = Iri::new(s)?;
accept_iri(validated);
```

### Owned IRI

```rust
struct Record {
    iri: IriBuf,
}

let iri = IriBuf::new("http://example.com".to_string())?;
let record = Record { iri };
```

### Temporary Parsing (Zero Allocation)

```rust
fn process_iri(s: &str) -> Result<(), IriError> {
    let components = Components::parse(s)?;

    println!("Scheme: {}", components.scheme());
    println!("Host: {:?}", components.authority());
    println!("Path: {}", components.path());
    Ok(())
}
```

### Owned Parsing with Component Access

```rust
fn process_iris(iris: Vec<String>) {
    for iri_str in iris {
        let components: Components<IriBuf> = Components::parse(iri_str).unwrap();

        println!("Scheme: {}", components.scheme());
        println!("Host: {:?}", components.authority());
        println!("Path: {}", components.path());
    }
}
```

### Parse from IriBuf

```rust
let owned = IriBuf::new("http://example.com/path".to_string())?;

let components: Components<IriBuf> = owned.components();
println!("Path: {}", components.path());
```

### Converting Between Variants

```rust
let borrowed: Components<&Iri> = Components::parse("http://example.com")?;

let owned: Components<IriBuf> = borrowed.to_owned();
let re_borrowed: Components<&Iri> = owned.as_borrowed();

assert_eq!(borrowed.scheme(), re_borrowed.scheme());
```

## 4. Why This Architecture is Optimal

### Key Advantages

1. ✅ **Path/PathBuf convention** - `Iri`/`IriBuf` follows Rust standard library naming
2. ✅ **Generic over storage** - `Components<S>` supports both borrowed and owned via single type
3. ✅ **Zero-alloc borrowed parsing** - `Components<&Iri>` needs no heap allocation
4. ✅ **O(1) component access** - Pre-computed positions for both variants
5. ✅ **Simple ownership** - `IriBuf` is just a tuple struct
6. ✅ **Compact positions** - u32 instead of usize (max 4GB IRI)
7. ✅ **Clear conversion paths** - `&Iri` ↔ `IriBuf` ↔ `Components<&Iri>` ↔ `Components<IriBuf>`

### Design Rationale

**Why `Iri(str)` as an unsized DST:**
- `&Iri` guarantees validity at the type level, not just via encapsulation
- No re-validation needed when constructing from `&Iri`
- Zero-cost: `#[repr(transparent)]` means `&Iri` has identical layout to `&str`
- Follows the `Path`/`PathBuf` convention from `std`

**Why `Components<S>` generic over storage:**
- Single type definition, shared accessor impl via `S: Borrow<Iri>`
- `Components<&Iri>` — zero-alloc temporary parsing (32 bytes, 0 heap)
- `Components<IriBuf>` — owned with O(1) access, no lifetime concerns (40 bytes, 1 heap)
- Seamless conversion: `to_owned()` / `as_borrowed()` between variants

### 6.2 Minimal vs Extended Metadata Trade-off

#### Minimal (32/40 bytes)
```rust
pub struct Components<S> {
    iri: S,
    scheme_end: u32,
    authority_end: u32,
    path_end: u32,
    query_end: u32,
}
```

**Pros:**
- Smaller stack footprint (32 bytes borrowed, 40 bytes owned)
- Faster to create (less parsing)
- Sufficient for most use cases

**Cons:**
- Need to re-parse for host/port/userinfo
- No pre-computed host type

#### Extended (64 bytes owned)
```rust
pub struct ComponentsExt<S> {
    iri: S,
    scheme_end: u32,
    authority_end: u32,
    path_end: u32,
    query_end: u32,

    host_type: HostType,
    port: Option<u16>,

```

**Pros:**
- O(1) access to host, port, host type
- No re-parsing needed
- Useful for network applications

**Cons:**
- Larger (64 bytes vs 40 bytes)
- More parsing upfront
- More complex

### 6.5 Authority Component Breakdown

The authority component has internal structure:
```
authority = [ userinfo "@" ] host [ ":" port ]

Examples:
- "example.com"
- "user@example.com"
- "user:pass@example.com"
- "example.com:8080"
- "user@example.com:8080"
- "192.168.1.1:8080"
- "[::1]:8080"
```

**Minimal approach:** Parse authority as a whole, re-parse when needed
**Extended approach:** Pre-compute host_bounds, port during initial parse
