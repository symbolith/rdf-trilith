# Complete Type Signature Analysis - Rust IRI Libraries

**Research Date:** 2026-01-29  
**Purpose:** Document actual type signatures across all major IRI/URI implementations

---

## Executive Summary

All major IRI libraries use one of three fundamental type system patterns:

1. **Generic over Spec (iri-string)**: Single generic type parameterized by IRI vs URI spec
2. **Generic over Storage (oxiri, fluent-uri)**: Generic over String/&str/Cow
3. **Borrowed vs Owned Pairs (iref)**: Separate types for borrowed and owned data

---

## 1. IRI-STRING Type System

### Architecture: Spec-Generic with DST Pattern

**Core Innovation:** Uses **Dynamically Sized Types (DST)** pattern - types are unsized and work like `str`/`String`.

### Generic Base Structure

```rust
/// Generic resource identifier slice (unsized, like str)
#[repr(transparent)]
pub struct RiStr<S> {
    _spec: PhantomData<fn() -> S>,  // Zero-sized spec marker
    inner: str,                      // Unsized inner data
}

/// Generic resource identifier string (sized, like String)  
pub struct RiString<S> {
    _spec: PhantomData<fn() -> S>,
    inner: String,
}
```

### Type Hierarchy

```text
RiReferenceStr<S>              (IRI reference - absolute or relative)
├── RiStr<S>                   (IRI - guaranteed absolute)
│   └── RiAbsoluteStr<S>       (IRI without fragment)
└── RiRelativeStr<S>           (Relative IRI reference)

Components:
- RiQueryStr<S>                (Query string component)
- RiFragmentStr<S>             (Fragment component)
```

### Spec Types

```rust
/// Marker type for IRI specification (RFC 3987)
pub struct IriSpec;

/// Marker type for URI specification (RFC 3986)
pub struct UriSpec;
```

### Public API Type Aliases

```rust
// Borrowed (zero-copy) types
pub type IriStr = RiStr<IriSpec>;
pub type IriReferenceStr = RiReferenceStr<IriSpec>;
pub type IriRelativeStr = RiRelativeStr<IriSpec>;
pub type IriAbsoluteStr = RiAbsoluteStr<IriSpec>;
pub type IriQueryStr = RiQueryStr<IriSpec>;
pub type IriFragmentStr = RiFragmentStr<IriSpec>;

// Owned (allocated) types
pub type IriString = RiString<IriSpec>;
pub type IriReferenceString = RiReferenceString<IriSpec>;
pub type IriRelativeString = RiRelativeString<IriSpec>;
pub type IriAbsoluteString = RiAbsoluteString<IriSpec>;
pub type IriQueryString = RiQueryString<IriSpec>;
pub type IriFragmentString = RiFragmentString<IriSpec>;

// URI equivalents (same pattern with UriSpec)
pub type UriStr = RiStr<UriSpec>;
pub type UriString = RiString<UriSpec>;
// ... etc
```

### Key Characteristics

✅ **Native String Semantics**: Types act like `str`/`String`  
✅ **Zero-copy**: Borrowed types have no allocation  
✅ **Type-level Spec**: Compile-time distinction between IRI/URI  
✅ **Memory Layout**: `#[repr(transparent)]` - same as `str`  

❌ **No Generic Storage**: Not generic over &str/String/Cow  
❌ **Runtime Component Access**: No pre-computed positions

### Metadata Structure

```rust
#[derive(Clone, Copy, Default)]
pub struct Meta {
    /// Index of trailing colon in scheme (NonZero means Some)
    pub scheme_end: Option<NonZeroUsize>,
    
    /// Authority metadata (host bounds, IP type)
    pub auth_meta: Option<AuthMeta>,
    
    /// Path start and end positions
    pub path_bounds: (usize, usize),
    
    /// One byte past last byte of query
    pub query_end: Option<NonZeroUsize>,
}

#[derive(Clone, Copy, Default)]

    pub host_bounds: (usize, usize),
    pub host_meta: HostMeta,  // Ipv4/Ipv6/IpvFuture/RegName
}

#[derive(Clone, Copy, Default)]
pub enum HostMeta {
    Ipv4(#[cfg(feature = "net")] Ipv4Addr),
    Ipv6(#[cfg(feature = "net")] Ipv6Addr),
    IpvFuture,
    #[default]
    RegName,
}
```

### Trait System

```rust
/// Trait for IRI/URI types (ref or owned)
pub trait RiMaybeRef {
    type Val;  // &str, String, etc.
    const CONSTRAINTS: Constraints;
    
    fn new(val: Self::Val, meta: Meta) -> Self;
    fn make_ref<'i, 'o>(&'i self) -> RmrRef<'o, 'i>
    where
        Self::Val: BorrowOrShare<'i, 'o, str>;
}

/// Trait for absolute IRI/URI types
pub trait Ri: RiMaybeRef {
    type Ref<T>: RiMaybeRef<Val = T>;
}

/// Parsing trait
pub trait Parse {
    type Val;
    type Err;
    fn parse<R: RiMaybeRef<Val = Self::Val>>(self) -> Result<R, Self::Err>;
}

// Implemented for &str and String
impl<'a> Parse for &'a str { ... }
impl Parse for String { ... }
```

### Key Characteristics

✅ **Generic Storage**: Works with &str, String, Cow<str>, Arc<str>  
✅ **Pre-computed Positions**: O(1) component access  
✅ **Zero-copy Validation**: Can parse borrowed strings  
✅ **Type-safe**: Separate Uri vs UriRef, Iri vs IriRef  

❌ **Complex Macro System**: Heavy use of declarative macros  
❌ **Large API Surface**: Many types and encoder variants

## 3. OXIRI Type System

### Architecture: Storage-Generic Minimal

**Core Innovation:** Simplest position-based design with const generic validation.

### Type Definitions

```rust
/// IRI reference (can be relative)
#[derive(Clone, Copy)]
pub struct IriRef<T> {
    iri: T,                              // Generic: &str, String, Cow<str>
    positions: IriElementsPositions,     // Just 4 × usize (32 bytes)
}

/// Absolute IRI (guaranteed to have scheme)
#[derive(Clone, Copy)]
pub struct Iri<T>(IriRef<T>);  // Newtype wrapper
```

### Position Structure

```rust
#[derive(Debug, Clone, Copy)]
struct IriElementsPositions {
    scheme_end: usize,      // 0 if no scheme (relative)
    authority_end: usize,   // End of "//authority"
    path_end: usize,        // End of path
    query_end: usize,       // End of "?query"
    // Fragment implicitly from query_end to end
}
```

### Parser with Const Generics

```rust
struct IriParser<'a, O: OutputBuffer, const UNCHECKED: bool> {
    iri: &'a str,
    base: Option<IriRef<&'a str>>,
    input: ParserInput<'a>,
    output: &'a mut O,
    output_positions: IriElementsPositions,
    input_scheme_end: usize,
}

trait OutputBuffer {
    fn push(&mut self, c: char);
    fn push_str(&mut self, s: &str);
    fn clear(&mut self);
    fn truncate(&mut self, new_len: usize);
    fn len(&self) -> usize;
    fn as_str(&self) -> &str;
}

// Two implementations:
impl OutputBuffer for String { ... }           // For actual output
impl OutputBuffer for VoidOutputBuffer { ... } // For validation only (zero allocation)
```

### Key Characteristics

✅ **Minimal Memory**: 32 bytes of positions only  
✅ **Zero Allocation Validation**: VoidOutputBuffer  
✅ **Generic Storage**: IriRef<&str> vs IriRef<String>  
✅ **Dual-Mode Parsing**: const UNCHECKED generic  
✅ **Type-safe**: Iri<T> vs IriRef<T>  

❌ **No Normalization**: Case-preserving  
❌ **Immutable**: Cannot modify components

## 7. Type System Design Patterns

### Pattern 1: DST (Dynamically Sized Type) - iri-string

```rust
// Like str vs String
#[repr(transparent)]
pub struct IriStr {
    inner: str,  // Unsized!
}

pub struct IriString {
    inner: String,  // Sized
}

// Usage
let borrowed: &IriStr = IriStr::new("http://example.com")?;
let owned: IriString = borrowed.to_owned();
```

**Pros:**
- Most familiar API (like String)
- Zero-copy borrowing
- Transparent memory layout

**Cons:**
- Component access requires parsing
- More complex implementation (unsized types)

---

### Pattern 2: Generic Storage + Metadata - fluent-uri, oxiri

```rust
pub struct Uri<T> {
    val: T,        // &str, String, Cow, etc.
    meta: Meta,    // Positions
}

// Usage
let borrowed: Uri<&str> = Uri::parse("http://example.com")?;
let owned: Uri<String> = Uri::parse("http://example.com".to_string())?;
let cow: Uri<Cow<str>> = borrowed.into();
```

**Pros:**
- Flexible ownership (generic over T)
- O(1) component access
- Single allocation for owned

**Cons:**
- Larger type size (storage + positions)
- More complex generic code

---

### Pattern 3: Borrowed/Owned Split - iref

```rust
pub struct Iri<'a> { ... }    // Borrowed
pub struct IriBuf { ... }     // Owned

// Usage
let borrowed: Iri = Iri::new("http://example.com")?;
let owned: IriBuf = IriBuf::new("http://example.com".to_string())?;
```

**Pros:**
- Clear ownership semantics
- Mutable owned types
- Simpler than generic over T

**Cons:**
- Type proliferation (2x types)
- Cannot be generic over ownership

---

### Pattern 4: Component-Based - uriparse

```rust
pub struct URI {
    scheme: String,
    host: Option<String>,
    // ...
}
```

**Pros:**
- Simplest API
- Easy mutation

**Cons:**
- Multiple allocations
- More memory usage

## 8. Recommendations for Universal Library

### Recommended Pattern: **Generic Storage + Metadata (Pattern 2)**

Like fluent-uri and oxiri, because:

1. **Flexibility**: Works with &str, String, Cow, Arc, Box
2. **Performance**: O(1) component access
3. **Memory Efficiency**: Single allocation when owned
4. **Zero-copy**: Can validate borrowed strings

### Proposed Type Signature

```rust
/// Generic IRI reference (can be relative)
pub struct IriRef<T: Deref<Target = str>> {
    data: T,                  // Storage: &str, String, Cow<str>, etc.
    positions: Positions,     // Pre-computed positions (32 bytes)
}

/// Absolute IRI (guaranteed scheme)
pub struct Iri<T: Deref<Target = str>>(IriRef<T>);

/// Position metadata (like oxiri, but with more detail like fluent-uri)
#[derive(Clone, Copy)]
struct Positions {
    scheme_end: u32,         // 0 = no scheme (relative)
    authority_end: u32,      // End of "//authority"
    path_end: u32,           // End of path
    query_end: u32,          // End of "?query"
    // Fragment is implicit from query_end to data.len()
    
    // Additional metadata (like fluent-uri)
    host_bounds: Option<(u32, u32)>,  // Within authority
    host_type: HostType,               // Ipv4/Ipv6/RegName
}

#[derive(Clone, Copy)]
enum HostType {
    RegName,
    Ipv4,
    Ipv6,
    IpvFuture,
}
```

### Usage Examples

```rust
// Zero-copy validation
let iri: IriRef<&str> = IriRef::parse("http://example.com")?;

// Owned
let iri: IriRef<String> = IriRef::parse("http://example.com".to_string())?;

// From borrowed to owned
let owned: IriRef<String> = borrowed.into();

// Cow for flexible ownership
let iri: IriRef<Cow<str>> = IriRef::parse(Cow::Borrowed("http://example.com"))?;

// Type-safe absolute check
let absolute: Iri<String> = iri.try_into()?;  // Fails if relative

// Const generic unchecked parsing
let iri: IriRef<&str> = IriRef::parse_unchecked("http://example.com");
```

## 9. Conclusion

The **generic storage + metadata pattern** (fluent-uri, oxiri) is the optimal choice because:

1. ✅ **One allocation** for owned types (vs multiple in component-based)
2. ✅ **Zero-copy** for borrowed types (vs copying in component-based)
3. ✅ **O(1) component access** (vs O(n) parsing in DST pattern)
4. ✅ **Flexible ownership** (works with &str, String, Cow, Arc, Box)
5. ✅ **Type-safe** (Iri<T> vs IriRef<T> distinction)
6. ✅ **Proven in production** (28M and 482K downloads respectively)

The main trade-off is **type size** (storage + positions), but the benefits far outweigh this cost.
